# glm-router

Экспериментальный локальный плагин-советник для ZCode Desktop. Он помогает выбрать между встроенными моделями подписки **GLM-5.3** и **GLM-5.3-Flash** и отдельно включает или выключает рассмотрение **OpenRouter**. Плагин не переключает модель основной сессии и не вызывает платный API.

English: local experimental ZCode advisor. It does not switch the main-session model, does not read app credentials, and leaves OpenRouter off unless you opt in with an explicit allowlist and a spending cap.

Версия пакета: 0.1.0. Проверялся локально на Node.js 22.23.4 (Linux). Целевая среда пользователя: macOS Apple Silicon и ZCode Desktop 3.17.2. На самом приложении ZCode этот пакет не запускался.

Публичный репозиторий: https://github.com/Jommmain/GLM-Roter-Zcode. Это выгрузка исходников локального прототипа 0.1.0. На ZCode Desktop 3.17.2 и macOS пакет по-прежнему не запускался.

## Что плагин делает

- Режим **ВЫКЛ** (`off`, значение по умолчанию): хук ничего не классифицирует, не советует и не блокирует.
- Режим **ПОЛУАВТО** (`semi`): локальная эвристика без дополнительного запроса к модели. В контекст хука `UserPromptSubmit` добавляется рекомендация и причины. Модель выбираете вы.
- Режим **ЭКСПЕРИМЕНТ: ПОДЗАДАЧИ** (`experimental-auto-subtasks`): тот же совет плюс текст о best-effort делегировании в отдельный контекст через инструмент Agent. Это не переключение основной сессии и не детерминированный маршрутизатор. Делегирование тратит дополнительные токены. Шаблоны субагентов не зарегистрированы.
- **OpenRouter** — отдельный переключатель, по умолчанию выключен. Выключение исключает все его маршруты, включая одноимённые GLM. Включение само по себе ничего не вызывает: нужна явная модель с префиксом (`z-ai/...` или `openrouter:...`) и лимит расходов. Идентификатор всегда состоит из провайдера и модели, например `zai-subscription::GLM-5.3` и `openrouter::z-ai/glm-5.3`.
- Глобальный режим ВЫКЛ перекрывает включённый OpenRouter.
- Если локально отмечено, что квота исчерпана, платный запасной маршрут не предлагается. Живую квоту плагин не читает и проценты остатка не хранит.
- Неясный запрос остаётся вопросом к вам, а не тихим маршрутом.
- Короткие одношаговые правки по эвристике ближе к Flash, многошаговые и рискованные — к полной GLM-5.3. Это настраиваемые пороги, не бенчмарк.
- Для встроенного канала Coding Plan документация ZCode описывает GLM-5.3-Flash как мультимодальную модель скриншотов. На другие провайдеры это не переносится.

## Чего плагин не делает

Публичные страницы ZCode, сверенные 6 ноября 2026 года, описывают поле `model` у команды как «Overrides the default model» и у субагента как конкретный id или `inherit`. Они не описывают срок действия переопределения и не объясняют, как отличить встроенную GLM от одноимённой модели OpenRouter. Команды `/model` и API смены модели основной сессии в этих страницах нет.

Поэтому команды `/glm-router-main` и `/glm-router-flash` не содержат поля `model`. Шаблоны в `glm-router/templates/agents/` не лежат в `agents/` и тоже не задают id модели. Пока привязка провайдера не проверена у вас в клиенте, исполнение закрыто: остаётся совет и ручной селектор.

Плагин не читает `~/.zcode`, не забирает ключи и не пишет сырой промпт. Поле `userConfig` в манифесте не используется: подстановка `${user_config....}` в документации показана для MCP, а не для хуков.

## Требования

- ZCode Desktop с открытым workspace.
- Node.js 18 или новее в `PATH`. Нативных модулей нет, установка `npm install` не нужна.
- Сеть плагину в рантайме не нужна.

## Установка

Каталог для магазина — тот, где лежит `marketplace.json` (корень этого архива), а не внутренняя папка `glm-router`.

1. Откройте проект в ZCode. Без workspace страница плагинов не работает.
2. Settings → Plugins → Create → Add marketplace. Укажите локальный каталог с `marketplace.json`. Клиент проверяет каталог до добавления.
3. В сегменте Personal найдите каталог `glm-router-local` и нажмите Install. Новый плагин включается сразу.
4. Откройте новый сеанс. Хуки снимаются снимком при старте сессии; уже открытый сеанс может их не подхватить.
5. Settings → Hooks. Записи плагина только для чтения: `UserPromptSubmit` и `PreToolUse` с matcher `Agent|Task`, исполнитель `node`, аргумент `${ZCODE_PLUGIN_ROOT}/hooks/glm-router-hook.mjs`. Файл `hooks/hooks.json` в манифесте повторно не указан: стандартный путь обнаруживается сам.

Проверка схемы каталога без ZCode:

```bash
node glm-router/bin/glm-router.mjs check-package
node glm-router/bin/glm-router.mjs status
```

Пока ZCode не подставил `ZCODE_PLUGIN_DATA`, конфиг пишется в `$XDG_DATA_HOME/glm-router/config.json` или `~/.local/share/glm-router/config.json`. Рядом сохраняется указатель `active-path.json` без секретов. Путь внутри `~/.zcode` отклоняется.

## Команды в чате

Имена берутся из файлов `commands/*.md`. Аргумент команды подставляется как `$ARGUMENTS`.

| Команда | Действие |
| --- | --- |
| `/glm-router-status` | режим, OpenRouter, путь конфига |
| `/glm-router-mode-off` | режим ВЫКЛ |
| `/glm-router-mode-semi` | режим ПОЛУАВТО |
| `/glm-router-mode-auto` | экспериментальные подзадачи |
| `/glm-router-openrouter-off` | выключить OpenRouter |
| `/glm-router-openrouter-on` | включить переключатель, не снимая лимит |
| `/glm-router-main` | как вручную выбрать встроенную GLM-5.3 |
| `/glm-router-flash` | как вручную выбрать встроенную GLM-5.3-Flash |
| `/glm-router-classify` | локальная классификация текста аргумента |

Команды с Bash просят агента выполнить один локальный `node bin/glm-router.mjs ...`. Это поведение агента документацией хуков не гарантируется. Надёжный путь — запустить CLI самим.

Полезные вызовы CLI:

```bash
node glm-router/bin/glm-router.mjs mode semi
node glm-router/bin/glm-router.mjs openrouter off
node glm-router/bin/glm-router.mjs openrouter on
node glm-router/bin/glm-router.mjs openrouter-cap --max-usd 1
node glm-router/bin/glm-router.mjs openrouter-allow --model z-ai/glm-5.3 --usd 0.2 --name GLM-5.3
node glm-router/bin/glm-router.mjs quota unknown
node glm-router/bin/glm-router.mjs classify --text "Исправь опечатку в заголовке"
```

`quota exhausted` — ваша локальная отметка, не чтение клиента. После неё советник не предлагает замену, в том числе OpenRouter. `quota available` и `quota unknown` возвращают обычную эвристику; unknown прямо говорит, что остаток не проверялся.

Голое имя `GLM-5.3` в список OpenRouter не принимается. Нужен различимый id.

Префикс `[[glm-router:bypass]]` в начале сообщения отключает совет для этого ввода и не зацикливает блокировку: обычные запросы хук не отклоняет.

## Дымовая проверка без платных вызовов

Подробный список: [docs/ACCEPTANCE.ru.md](docs/ACCEPTANCE.ru.md).

Кратко: при режиме ВЫКЛ контекст советника не появляется. После `mode semi` и нового сеанса фраза «Исправь опечатку в заголовке» должна дать совет в пользу встроенной GLM-5.3-Flash и идентификатор `zai-subscription::GLM-5.3-Flash`, без выбора OpenRouter. «сделай хорошо» должно просить уточнение, а не блокировать ввод. Команды main/flash не должны менять имя модели в селекторе. Если недельная или 5-часовая квота не даёт живой ответ модели, на этом остановитесь: хук можно сверить на экране Hooks, не отправляя платный запрос.

Локальные тесты, уже выполненные вне ZCode:

```bash
npm test
```

## Удаление

1. Settings → Plugins → Manage installed. Переключатель выключает компоненты; пункт плагина снимает его с машины.
2. Значок шестерёнки над поиском → Marketplace sources → Remove this marketplace для `glm-router-local`.
3. Удалите локальный конфиг по пути из `node glm-router/bin/glm-router.mjs path` и указатель `active-path.json` в том же каталоге `glm-router`, если он есть. Не удаляйте `~/.zcode/v2/config.json`: там провайдеры и ключи приложения, этот пакет их не использует.

Отключение плагина убирает его компоненты из сессии. Для хуков надёжнее новый сеанс, потому что конфигурация хуков фиксируется на старте.
